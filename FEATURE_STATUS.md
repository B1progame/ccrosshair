# Feature coverage and verification

Status reviewed 2026-10-05. “Implemented” describes checked code paths; it does not imply that every Windows/game combination has been exercised.

| Requirement | Status | Evidence / limitation |
|---|---|---|
| React control surface backed by the native typed bridge | Implemented/tested | Snapshot reconnect, validated commands, Python owns native windows and settings. Windows WebEngine uses software composition to avoid the reproduced D3D shared-image context-loss black screen. |
| Live zoom, `N` activation hold/toggle, adjustable steps/presets, focus suppression, latest-frame queue, stale-session rejection, capture-feedback exclusion, optional crosshair hiding and diagnostics | Implemented/tested; native game behavior unverified | `N` is the default (the shipped `Ctrl+Alt+Z` default migrates; user bindings persist). Hold and edge-triggered toggle modes are available. React text entry suppresses activation. User can hide and restore the overlay during a visible zoom session. The worker scaling enum regression is fixed and quality worker emits frames. Desktop capture/scaling benchmark is measured below. No gameplay frame-age/FPS or mixed-DPI gameplay benchmark has been run. |
| Local AI super-resolution and comparison against conventional scaling | Implemented experimentally; source integration tested | Quality mode lazily loads a bundled checksum-verified ONNX Model Zoo 3× model in the zoom worker, prefers ONNX Runtime DirectML, falls back to CPU or spatial scaling, and reports the actual provider/model in diagnostics. Fast/Balanced do not initialize inference. Frozen app contains the model, license, ORT, NumPy, and DirectML DLLs; source worker/inference is tested on DirectML. Synthetic benchmark is recorded below; the model does not consistently improve all quality metrics and its p95 inference time exceeds the 33 ms capture cadence. No gameplay/model-content validation exists. The AI Zoom page is now visible without enabling the former beta preference. The game framebuffer and its built-in reticle are not rewritten. See [`MODEL_NOTICE.md`](src/crosshair_overlay/assets/models/MODEL_NOTICE.md). |
| 310 distinct offline catalog entries and practical/novelty geometry families | Implemented/tested | Preserves the 100 v1.2.3 entries and adds 150 practical plus 60 novelty/joke patterns. Tests check distinct geometry and render/serialize every added pixel design. Designs are original, not copied player presets. See [`CATALOG_SOURCES.md`](CATALOG_SOURCES.md). |
| Search/filter, aliases, game and author metadata, favorites and recent use | Implemented/tested; synthetic benchmark measured | Native handler caches each immutable definition's normalized searchable text. On the listed hardware, `tools/benchmark_catalog_search.py` measured p50/p95 hot search at 100: 0.13/0.18 ms; 1,000: 0.68/2.60 ms; 10,000: 14.86/39.99 ms, with 36 results per page. The cold 10,000-item query is 43.22 ms. UI rendering, full catalog memory, first useful paint, and animation cost are outside the benchmark. |
| Crosshair color/opacity/outline, recent palette and appearance import/export | Implemented/tested partly | Color and outline data round-trip through definitions; live color/outline controls and background previews exist. Per-game independent appearance profiles and adaptive contrast sampling/lock are not implemented. |
| Input-reactive fire pulse, gap/opacity changes, ADS hold/toggle, emergency hide, reduced-motion behavior | Implemented/tested partly | Foreground mouse observation only; click means attempted fire. A press-only pulse or user-configurable repeat cadence while holding the primary mouse button is available globally and per loadout. ADS can follow hold or press-to-toggle, and each game loadout can select a separate ADS style/color/opacity/outline or hide on ADS. Duration, amplitude, fade, and emergency binding are configurable. Keyboard fire binding and true weapon-state telemetry are not supported. Reduced motion disables native pulses and makes fades immediate. |
| Remove built-in game crosshair without modifying the game | Blocked by capture architecture | Captured desktop pixels have already composited the game reticle. There is no supported game API integration in this app; reconstructed pixels cannot remove it from the game framebuffer. No game files/memory are changed. |
| Experimental crosshair reconstruction inside processed Zoom view | Experimental; synthetic tests pass; native runtime unverified | Optional small manual center circle, strength, mask-boundary preview and boundary-contrast abstention run in the Zoom worker before scaling when a configured game profile is active. Unmasked pixels are preserved and tests verify improvement on a synthetic linear gradient. It is a simple interpolation baseline, not AI inpainting; dynamic reticles, motion, and gameplay scenes are unvalidated. |
| Named multi-loadouts per game, cycling/favorite shortcuts, manual override and restore | Implemented/tested partly | Profiles persist up to 20 named loadouts with separate hip-fire and ADS styles/appearance, Zoom, and input-reactive settings. User-rebindable next/previous/favorite shortcuts cycle while the mapped game is foreground. Existing foreground switching restores the previous manual style and global Zoom/reactive settings when leaving the game. UI controls and bridge validation are covered by regression tests; real gameplay switching still needs native runtime validation. |
| Creator draw/erase, undo/redo, save/import/export | Implemented/tested partly | Layered v3 designs support independently editable/visible draw, cross, dot, ring, and bracket layers while keeping the visible flattened geometry and accepting legacy v2 files. Pointer capture is best-effort, drag strokes interpolate skipped cells, and an embedded React/WebEngine regression verifies continuous drawing. The editor also provides grid snapping, keyboard navigation/painting, recovery, transforms, duplicate, save and export. Saves return the saved ID and propagate disk errors to the UI. Windows hands-on keyboard testing remains outstanding. |
| Compare 2–4 styles, center-offset and per-monitor calibration | Implemented/tested partly | Library comparison keeps two to four selected styles on the same selectable light/dark/textured background. Per-monitor ±128 Qt-coordinate offsets persist through schema v6 and the native bridge, and apply to the real overlay when positioned over that display. Comparison is a static preview; scaling/aspect-ratio analysis and live calibration on mixed-DPI hardware remain unverified. |
| Collections, bulk tags/export, duplicate detection and import conflict preview | Implemented/tested partly | Collections and custom tags persist; selected styles can be tagged, exported together, queried by collection/tag, and checked for exact-geometry duplicates. Import previews ID/name conflicts and offers keep existing, import-as-copy, or replace with backup. Replacement is enabled only when every collision maps to a user-created `.xhair` inside the custom library; imported originals are copied into the import bundle before atomic replacement. Catalog, creator-layer, and external files cannot be replaced. Windows dialog interaction has not been hands-on tested. |
| Settings migration, atomic writes, backup and corruption recovery | Implemented/tested partly | Schema validation and preservation/recovery of valid backup are covered by tests. Reset previews affected preference groups and retains crosshair files. Settings now include a grouped backup preview and explicit restore confirmation; a fingerprint prevents restoring a backup that changed after preview, and current settings become the new backup. Restart is required to apply restored settings. A field-by-field preview/restore chooser for automatic schema migrations is still absent. |
| Accessibility and diagnostics export | Implemented/tested partly | High contrast, density, text scale, reduced motion affects React, native pulses and Zoom entrance animation; sanitized diagnostics include cleanup state and save preview. Full keyboard-only creator drawing has no dedicated accessibility verification. |
| Runtime presets, thermal/GPU adaptation and manual lock | Implemented/tested partly | Runtime mode sets preview cadence; opt-in NVIDIA telemetry polls every 5 seconds, reduces active preview cadence after three hot/high-load readings, restores after six cool readings, and leaves the selected mode unchanged when unavailable. Manual selected mode stays locked when adaptation is disabled. It does not adapt AI inference budgets or capture size; only NVIDIA `nvidia-smi` telemetry is supported and gameplay impact is unverified. |
| Capture compatibility check and per-game hide instructions | Partly implemented | Compatibility page can probe/discard a 2×2 Qt desktop sample per display and reports logical bounds, negative origins, and device-pixel ratio. It explicitly does not claim this verifies game capture. VALORANT guidance links Riot's historical in-game `Disable Crosshair` option and asks users to recheck the current menu; CS2's source-linked entry covers native crosshair settings but does not claim a hide switch. The app makes no game changes. Exclusive fullscreen, protected surfaces, and current game menus still require manual device validation. |

## Verification performed

- `PYTHONPATH=src .venv/Scripts/python.exe -m unittest discover -s tests -q`: 78 tests passed, including custom creator/zoom regressions, embedded creator drawing, hold/toggle activation, repeat cadence migration, restore-preview safety, per-display capture probing, rendered/serialized checks for all new designs, actual local AI inference, React WebEngine checks for visible AI Zoom controls and compatibility guidance, and frozen-runtime filtering of foreign Qt/ICU PATH entries.
- `npm run build` in `frontend`: TypeScript and Vite production build passed.
- `python -m compileall -q src/crosshair_overlay`: passed after the calibration changes.
- The one-directory Windows executable is rebuilt and launch-checked for release v1.4. This task host blocks Qt WebEngine's nested Chromium sandbox; only the smoke-test process sets `QTWEBENGINE_DISABLE_SANDBOX=1`. The distributed application does not disable WebEngine sandboxing. Foreign Poppler ICU DLLs are excluded at build time and incompatible Qt/ICU PATH entries are filtered before PySide6 imports.
- `tools/benchmark_catalog_search.py` measures cold and repeated native query-handler latency at 100, 1,000, and 10,000 definitions (50 repeated searches, 36 results per page); its memory figure is temporary query allocation only, not total library memory or UI paint.
- A repeatable current-desktop capture/scaling benchmark is in [`tools/benchmark_zoom_capture.py`](tools/benchmark_zoom_capture.py). On AMD Ryzen 7 7700X + NVIDIA GeForce RTX 5060 Ti, Windows 11 build 26200, 320×180 `QScreen.grabWindow(0)` crops scaled to 1280×720 (10 warmup + 180 measured frames per mode): Fast p50/p95 capture 7.28/9.16 ms, scaling 1.17/1.70 ms, total 8.42/10.92 ms; Smooth p50/p95 capture 4.68/10.96 ms, scaling 3.86/4.29 ms, total 8.53/15.21 ms. This serial desktop microbenchmark excludes a running game, overlay presentation, AI inference, concurrent capture/render contention, and gameplay impact; it is not a game-FPS claim.
- [`tools/benchmark_zoom_ai.py`](tools/benchmark_zoom_ai.py) measured the bundled 240,078-byte model on that same PC with DirectML: 320×320 source crop to 224×224 model input and 672×672 output, 15 warmups + 120 measured frames. Inference plus conversion p50 23.23 ms, p95 35.23 ms, 39.97 serial frames/s. On one synthetic thin-grid/reticle target, bicubic scored MAE 12.9567 / PSNR 19.2283 dB and AI scored MAE 13.0721 / PSNR 20.2537 dB. The model improved PSNR by about 1.03 dB but had slightly worse MAE; one synthetic target is not sufficient evidence of general quality gain. At p95 it can miss the app's 33 ms capture interval, so latest-frame dropping is expected under load and visible in diagnostics.
- Monitor/DPI matrix, AI-model comparison, gameplay frame-time impact, and before/after application screenshot remain outstanding.
